Overview of Git:
=================================================================================================
GIT: Global Interaction Tool

Git is an source code management tool which is used for storing the code, important files, automation files etc which uses distributed version control system mechanism which provides proper tracking and also benefit of storage cost optimization.

---------------------------------------------------------------------------
Why Git ?
---------------------------------------------------------------------------
* What is version control system: 
----------------------------------------
Version control system(VCS) is an mechanism which provides unique identification for storing the data inside the files using commit_id(SHA key) which uses algorithm "Secure hashing algorithm" which is in the form hexa decimal code 125/256 bytes.

eg: commit_id: zasdf82hfdkd9dh24nkfjf83nf4

----------------------------------------------
* Why Version control system(VCS):
----------------------------------------------
1. Tracking: Proper tracking in Version control system
         * Who  - each and every user modified details - username & email - capture this info initially.
         * When - every user modified time & date
         * What - everything added/deleted/modified

2. Storage cost optimization: Avoid the duplication of the data.

eg: Ecommerce-application:

Login feature:
  DAY-1: login.java(10 lines) -> 1 GB -> Build and execution -> working fine.
              Record the changes -> jskdkddnqwdod3rn4rnef3323efefwf

  DAY-2: login.java -> 5 GB -> Build and execution -> working fine.
              Record the changes -> lkkjhdbdwqwd2212dddedfo9udqd2d

----------------------------------------------
* Traditional system: Linux/Windows
----------------------------------------------
1. Tracking: No proper tracking in Traditional system
         * Who  - last user modified details - username
         * When - last user modified time & date
         * What - we don't know whether added/deleted/modified - ?

2. Storage cost optimization: Avoid the duplication of the data - not possible.

eg: Ecommerce-application:

Login feature:
  DAY-1: login.java -> 1 GB -> Build and execution -> working fine.

         backup_login.java_day_1 -> 1 GB

  DAY-2: login.java -> 1 GB + 5 GB -> Build and execution -> working fine.

         backup_login.java_day_2 -> 6 GB

  DAY-3: login.java -> 6GB + 10 GB = 16 GB -> Build and execution -> working fine

===================================================================================================
Types of Version control system:
===================================================================================================
1. Centralized version control system:

* no parallel development
* high changes of data loss
* online connection - internet connection
* Licence tool
 
eg: clearcase, SVN etc

----------------------------------------------------------------
2. Distributed version control system

* parallel development
* no chances of data loss
* offline connection - less internet connection
* open source tools - free trail or version
                    - subscription - support
           
eg: Git, Github, bitbucket etc

=====================================================================================================================
Architecture of Git:
=====================================================================================================================
There are four states for your files to be in when you’re working with Git. These three states 
are: Working, staging, local and remote 

1. Working Directory: 
    When you make changes to a file in your working directory, it is then modified, but these modifications 
are not stored in the codebase. 

2. Staging Area: 
    When you stage the file, these changes are marked to be saved in the next commit.
  
3. Local Repo: 
      When you commit the file, these changes are finally stored in your codebase. This you have a local 
repository on your machine, that is your desktop or laptop, which is defined in your working directory 


4. Remote Repo: 
       A remote repository that is stored on the cloud. Eg: Github

Standard branches:
-------------------------------------------------------------------------------------------------------------------
1. master/main: Master/Main is an unique branch which is created by default at the time of repository creation.
                Master/Main will always have up-to-date code which is used for customer releases or customer demos.
                There will be only one master/main branch.

eg: master/main

---------------------------------------------------------------------------------------------------------------------------
2. develop branch: Develop branch is used for development and testing phase activities.
                   There will be only one develop branch.

eg: develop
---------------------------------------------------------------------------------------------------------------------------
3. release branch: release branch is used for maintaining customer release wise changes for releasing/deploying into specific environments.
                   There will be multiple release branches.

eg: release, release-Q1, flipkart-release-2026-Q1 etc

----------------------------------------------------------------------------------------------------------------------------
4. feature branch: feature branch is used for development and testing phase activities where develop branch code is dividing into the feature branches for easy development and testing via small modules.
                   There will be multiple feature branches.

eg: feature/feature_name, feature/feature_ticket, feature/feature_date etc

----------------------------------------------------------------------------------------------------------------------------
5. hotfix branch: hotfix branch is used for fixing the live issues reported by customers.
                  There will be multiple hotfix branches.
   
 eg: hotfix/hotfix_name, hotfix/hotfix_ticket, hotfix/hotfix_issue etc


Apart from above branches, we can keep any naming convention branches.

Tags:
=====================================================================================================================
Tag is an unique identification or bookmark or label which is used for marking the commits as stable point of release.

 eg: v1.0, v1.1, stable-release-Q1, R.10, fix-2026 etc

eg: commit-1
    commit-2
    .
    .
    .
    commit-50 - verified-fix, delta-customer-release, fix-Q3 etc
    . 
    .
    .
    commit-100

commands: git tag  -l                   // list all tags
          git tag tag_name              // create an tag and assign tag to latest commit
          git tag tag_name commit_id    // create an tag and assign tag to specific commit
          git tag -f tag_name commit_id // retag the tag to other commit
          git tag -d tag_name           // delete an tag

Note: same tag cannot be applied on multiple commits.
      commit can have multiple tags.
